# Root-Cause Debugging & Implementation Follow-Up: Mushaf Pages & Ayah Reader

## 1. Observed Root Causes with file:line Anchors

### A. Mushaf Page-Number & Metadata Inconsistencies
- **`src/lib/quran.ts:686-695`**: `fetchMushafPage` previously accepted cached data if `cached.pageNumber === safePage && Array.isArray(cached.ayahs) && cached.ayahs.length > 0`. It did not verify whether the individual cached ayahs actually matched `safePage`. Any stale cache payload could result in mismatched page data.
- **`src/lib/quran.ts:807-825` & `src/lib/quran.ts:850-875`**: Fallback and API response mappings selected `juz` and `hizbQuarter` using `ayahs.find((a) => typeof a.juz === 'number')?.juz`. If an ayah object had an unpopulated or out-of-range value (or if the first ayah had invalid metadata), `juz` or `hizbQuarter` defaulted to `undefined`, leading to blank or missing Juz/Hizb badges in the header and footer.
- **`src/screens/QuranReaderScreen.tsx:1420-1450`**: Navigating pages in Mushaf mode did not clear previous ayah selection coordinates (`selectedAyahY`, `selectedAyahHeight`), causing previous selection overlays to linger or appear at invalid positions.

### B. Compact Ayah Popup Anchoring
- **`src/screens/QuranReaderScreen.tsx:2570-2640`**: In the normal Uthmani rendering branch, ayahs were rendered inside nested `<Text>` components within a parent `<Text style={styles.mushafPageBodyText}>`. React Native cannot reliably measure or return layout coordinates (`x`, `y`, `width`, `height`) for nested `<Text>` inline elements.
- **`src/screens/QuranReaderScreen.tsx:1515-1540`**: `handleSelectMushafAyah` and `handleLongPressMushafAyah` set `selectedAyah`, but did **not** update `selectedAyahY` or `selectedAyahHeight`. Because `onLayout` only fires once during mount/layout calculation and not upon touch selection, `selectedAyahY` remained stuck at 0 (or header top), displaying the action popup at the top of the viewport rather than anchored to the selected ayah.
- **`src/screens/QuranReaderScreen.tsx:4967-4985`**: Popup styles (`mushafInlineSelectedToolbar`) lacked elevation/shadow contrast and dynamic offset bounds checking, causing the popup to clip or detach from the viewport.

### C. Blank Screen on Mode Switch (Mushaf Pages -> Ayah by Ayah) & Page 2 Navigation
- **`src/screens/QuranReaderScreen.tsx:1137-1162` (Fatal FlatList Invariant Crash)**:
  `handleViewableItemsChanged` previously included `[surah?.englishName]` in its `useCallback` dependency array. When switching from Mushaf Pages to Ayah by Ayah (`cards`), the mode toggled and initiated a background fetch (`fetchSurah`). Approximately 1 second later, the fetch resolved and updated `surah.englishName` (e.g., from generic to `"Al-Baqara"`). This instantiated a new callback instance for `onViewableItemsChanged`. In React Native Web's `FlatList.componentDidUpdate`, an invariant check executes:
  `invariant(prevProps.onViewableItemsChanged === this.props.onViewableItemsChanged, 'Changing onViewableItemsChanged on the fly is not supported')`.
  In React 19, this thrown invariant violation unmounted the entire component tree, leaving `document.body.innerText` at length 0 after 1 second.
- **`src/screens/QuranReaderScreen.tsx:2802-2824` (Full-Screen Unmounting Guard)**:
  The screen previously had top-level early returns `if (readingMode === 'cards' && loading && !surah)` and `if (error && !surah)`. This unmounted the entire reader navigation shell (nav bar, back button, surah titles) and rendered an isolated `ActivityIndicator` with 0 text nodes.
- **`src/screens/QuranReaderScreen.tsx:2556-2603` (Footer Page 2 Navigation & Juz Structure)**:
  When on Page 1 (Al-Fatihah), clicking the next page button (`mushaf-footer-next-btn`, displaying `"Page 2"`) navigates to Page 2 (Al-Baqarah 2:1-5). Canonically in the Quran, Juz 1 spans pages 1 through 21 (Hizb 1 spans pages 1 through 11). Thus, Page 2 belongs to `Juz 1 • Hizb 1`. Any smoke assertion asserting `!body.includes('Juz 1')` on Page 2 was an invalid canonical assumption; Page 2 correctly displays `Juz 1 • Hizb 1`, while visible page labels advance to `Page 2 of 604`, the next button advances to `Page 3`, and the previous button displays `Page 1`.

## 2. Files Changed

1. **`src/lib/quran.ts`**:
   - Added cache isolation validation: `cached.pageNumber === safePage && cached.ayahs.every((a) => !a.page || a.page === safePage)`.
   - Guaranteed numeric range validation for `juz` (1..30) and `hizbQuarter` (1..240).
   - Enforced `page: safePage` on all returned ayah objects.

2. **`src/screens/QuranReaderScreen.tsx`**:
   - Bound `handleViewableItemsChanged` to `surahRef = useRef(surah)` with empty `[]` dependencies, permanently preventing the FlatList invariant violation on mode toggle and network resolution.
   - Removed top-level early returns (`if (loading && !surah)`) that unmounted the reader shell; moved cards loading/error states inside the reader frame with localized visible text `{t('Loading surah...')}`.
   - Added `immediateSurah` pre-population in `handleToggleReadingMode` from `currentPageData.ayahs` and `getBundledSurahs114()`, ensuring cards mode has immediate data without delay.
   - Ref-guarded `initialPage` and `safeSurahNumber` synchronization effects (`lastInitialPagePropRef`, `lastSurahPropRef`) so in-reader page navigation is not reverted on re-render.
   - Added dynamic `key={`cards-surah-${safeSurahNumber}`}` to FlatList for clean remounting between surahs.
   - Added deterministic testIDs: `mushaf-footer-prev-btn`, `mushaf-footer-badge`, `mushaf-footer-next-btn`, `mushaf-nav-prev-btn`, `mushaf-nav-next-btn`.
   - Maintained compact ayah popup anchor with measured `{ y, height }` coordinates for both Uthmani and Tajweed branches.

3. **`tests/test_reader_tools_menu.mjs`**:
   - Added **Test 12**: Mushaf page cache safety and zero un-interpolated token leaks (`{p}`, `{n}`, etc.).
   - Added **Test 13**: Ayah popup anchoring with measured layout coordinates in both branches.
   - Added **Test 14**: Reading mode switch resilience and blank-screen protection.

## 3. Exact API & Cache Contract Verified

- **Remote API Endpoint**:
  `GET https://api.alquran.cloud/v1/page/{page}/quran-uthmani`
  Verified with live queries for pages 1, 2, 600, 604. Returns HTTP 200 with JSON payload containing:
  - `data.ayahs`: array of ayah records containing `number`, `text`, `surah`, `page`, `juz`, `hizbQuarter`.
  - `data.surahs`: dictionary of surah metadata on multi-surah pages.
- **Cache Contract**:
  - Key: `mushaf-page:${page}:${edition}` (or `mushaf-page:${page}:quran-uthmani`).
  - Cache Read Validation: `cached.pageNumber === safePage && cached.ayahs.length > 0 && cached.ayahs.every((a) => !a.page || a.page === safePage)`. Cached payload for page N is strictly rejected if requested for page M.
  - Page Number Alignment: `currentPage`, `currentPageData.pageNumber`, `displayedMushafPage`, header title, footer pagination buttons, and continue reading marker all resolve to the identical evaluated integer page number.

## 6. Known Limitations Requiring Physical Android Verification

1. **Touch Responder Delay**: On lower-end Android hardware, a 500ms long-press responder inside nested scroll views should be verified to confirm no gesture conflicts with vertical scrolling.
2. **Edge-to-Edge Window Insets**: Dynamic keyboard avoiding on Android devices with deep notches or navigation bars should be verified when creating notes from the ayah popup.
