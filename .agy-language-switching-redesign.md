# App Language Settings Redesign & Hardening Report

## 1. Executive Summary & Root Cause Analysis

### Previous Design Defects
1. **Cards-Inside-a-Card Antipattern**: The previous implementation rendered a grid of individual border-framed rectangular cards (`langCard`) nested inside a settings `Card`. This violated the app's calm editorial design system, creating visual clutter and artificial boxing.
2. **Horizontal Cramping on Narrow Phones**: On compact viewports (320px–380px), dividing available width into 2 columns squeezed each card down to 148px–154px. Subtitle text such as `English · Left to Right (LTR)` had to force font scaling down to 0.85 with `adjustsFontSizeToFit` to avoid clipping.
3. **Fragile Grid Wrapping & Scalability Issues**: Hardcoding 2-column and 3-column breakpoint math caused awkward trailing orphan cards whenever the language count was odd or non-multiple of the column count.
4. **Weak Selected Hierarchy**: The previous radio indicator was an ordinary checkbox in the corner of a box, lacking high-contrast editorial hierarchy and calm Islamic-app visual polish.

---

## 2. Design Decisions & Visual Direction

### Calm Editorial Islamic-App Visual Direction
- **Vertical Selectable List**: Converted the language options into full-width selectable rows inside the Section's `<Card padded={false}>` surface, separated by subtle `<Hairline />` dividers.
- **Authentic Script Typography**:
  - Urdu (`اردو`) & Arabic (`العربية`): Rendered using `NotoNaskhArabic_700Bold` at 17–18px font size with generous vertical padding, guaranteeing that Arabic/Urdu nuqtas (dots) and diacritics are crisp and never clipped.
  - English (`English`), Hindi (`हिन्दी`), Malayalam (`മലയാളം`), Sinhala (`සිංහල`): Rendered with `Manrope_700Bold` at 15–16px.
- **Direction Badges**: Each option features a compact, elegant pill badge displaying `RTL` or `LTR` directly adjacent to the native script name.
- **Localized Subtitle**: Displays the language name in the active app locale (`getLocalizedLanguageName(opt.englishName)`), providing immediate context in the user's active tongue.
- **Intentional Selected State**:
  - Row surface softly tinted with `colors.accentDim`.
  - Native title and subtitle highlighted with `colors.accent`.
  - Circular accent checkmark badge (`colors.accent` background, `colors.onAccent` checkmark icon).
- **Unselected State**:
  - Clean card surface background.
  - Primary text in `colors.textPrimary`, subtitle in `colors.textSecondary`.
  - Crisp, understated radio circle (`colors.borderStrong`).
- **In-Flight Feedback & Protection**:
  - Target language row displays an inline `ActivityIndicator` in `colors.accent`.
  - Non-target rows dim to `opacity: 0.55`.
  - All rows disabled during switch.
- **Error State**: A designated error banner with `Ionicons` alert icon renders at the base of the card if persistence or readback fails.
- **Accessibility & Touch Targets**:
  - `minHeight: 54px` (exceeding the >=44px mobile touch target requirement).
  - Padded with canonical `touchTargetTokens.hitSlop8`.
  - Exposes `accessibilityRole="radio"`, `accessibilityState={{ selected, disabled }}`, and full descriptive `accessibilityLabel`.
- **Linear Scalability**: Seamlessly scales to 7, 8, 10, or 20 languages without ragged rows, orphan cards, or breakpoint math.

## 3. Language Switching Hardening

### Concurrency & Persistence Contract
1. **Synchronous Press Debouncing**: Guarded by `isSwitchingLanguageRef.current`. First tap sets ref synchronously; rapid double-taps or multi-touch bursts are discarded immediately before entering async queue.
2. **Shared Write Queue (`settingsWriteQueue.ts`)**: Every language change persists through `createSerializedSettingsWriter`, guaranteeing FIFO ordering and atomic execution.
3. **Durable Write & Atomic Readback**: Data is serialized to `AsyncStorage` and immediately read back and JSON-parsed. If the readback language does not match the target, an error is thrown.
4. **Rollback Isolation**: On write or readback error:
   - Only the `language` field is restored to `prevLang`.
   - Concurrent updates (e.g. `themeMode`, `accentKey`) are preserved.
   - In-memory `setAppLanguage` is reverted.
   - Zero `prepareNativeLayoutDirection` call.
   - Zero `Updates.reloadAsync` call.
   - Error surfaced cleanly to UI state.
5. **Layout Direction & Native Reload Ordering**:
   - `prepareNativeLayoutDirection(nextLang)` is called AFTER storage verification and immediately before scheduling reload.
   - On native: `allowRTL(isRtl)` and `forceRTL(isRtl)` write native layout preferences to disk.
   - 400ms timer scheduled before calling `Updates.reloadAsync()`.
   - Unmount during in-flight switch preserves the reload timer so the restart is not dropped.
