# SettingsScreen App Language Section Redesign

## 1. Exact Root Cause Analysis

Prior to this redesign, the App Language section in `src/screens/SettingsScreen.tsx` used the generic `Segmented<AppLanguage>` pill component:
1. **Asymmetrical flex wrapping & stretched trailing items**:
   `Segmented` renders options inside `styles.segRow` (`flexDirection: 'row', flexWrap: 'wrap', gap: 6`), where each pill child has `styles.seg` (`flex: 1, minWidth: 54, minHeight: 40`). Because each item was assigned `flex: 1`, flexbox attempted to pack as many items as possible on the first line (5 items on typical 360–390px mobile screens), causing the 6th item (`සිංහල`) to wrap to the second line alone. Under `flex: 1`, that single item expanded to 100% of the row width, creating an uneven layout.
2. **Narrow-viewport text clipping & multi-script crowding**:
   On devices with widths < 360px (such as 320px iPhone SE), 6 horizontal pills with diverse scripts (e.g. Malayalam `മലയാളം`, Arabic `العربية`, English `English`) were cramped into ~45–50px each, causing text truncation and overlapping.
3. **Inability to scale as new languages are added**:
   Horizontal segmented controls are designed for 2–4 short, mutually exclusive state toggles (like Theme: System/Dark/Light). As the app adds more languages (e.g. Turkish, Bengali, French, Indonesian, etc.), horizontal pills become completely unusable.
4. **Touch target accessibility deficiency**:
   `styles.seg` defined `minHeight: 40`, falling short of the modern mobile accessibility standard requiring minimum touch targets of at least 44px.

## 2. Redesign Architecture & Solution

### A. Dynamic Responsive Card Grid
Instead of a horizontal segmented control, the language picker now uses a responsive card grid powered by `APP_LANGUAGE_OPTIONS` and runtime layout metrics:
- **Available Width Computation**:
  ```ts
  const availableLanguageWidth =
    Math.min(layout.width - layout.screenPad * 2, layout.maxW) - layout.cardPad * 2;
  ```
- **Adaptive Columns (No Hardcoded 4/7-Column Assumptions)**:
  - **1 Column**: Ultra-compact / narrow devices (< 280px available width, e.g. 320px phone). Each card spans full width (264px), preventing any clipping.
  - **2 Columns**: Standard mobile phones (280px to 500px available width, e.g. 360px–430px). Cards have width 148px–175px, arranged in balanced 2-column rows.
  - **3 Columns**: Tablets, foldables, and desktop/web (>= 500px available width). Cards have width 169px–196px.
- **Fixed Card Width (`languageCardWidth`)**:
  Calculated as `Math.floor((availableLanguageWidth - (languageColumns - 1) * languageGap) / languageColumns)`. Cards do NOT use `flex: 1`, ensuring that when new languages are added (e.g., a 7th or 9th language), trailing cards maintain the exact same width as all other cards rather than expanding across the row.

### B. Visual & Typography Polish
- **Touch Target**:
  Cards have `minHeight: 52` (exceeding the >= 44px threshold) with `hitSlop={touchTargetTokens.hitSlop8}`.
- **Authentic Native Script Typography**:
  - Urdu (`اردو`) & Arabic (`العربية`): Rendered in `NotoNaskhArabic_700Bold` with `writingDirection: 'rtl'`.
  - English (`English`), Hindi (`हिन्दी`), Malayalam (`മലയാളം`), Sinhala (`සිංහල`): Rendered in `Manrope_700Bold` with system font shaping.
- **Localized Secondary Label & Reading Direction**:
  Displays `${getLocalizedLanguageName(opt.englishName)} · ${opt.direction}` (e.g. `English · LTR`, `Urdu · RTL`, `Arabic · RTL`), localized according to the active app UI language.
- **Selection State & RTL Mirroring**:
  - Selected cards use `colors.accent` border and `colors.accentDim` background.
  - Radio circle indicator uses `marginStart: 8` for symmetrical spacing, naturally placing the indicator on the trailing edge in both LTR (right) and RTL (left).
- **Accessibility**:
  `accessibilityRole="radio"`, `accessibilityState={{ selected: isSelected, disabled: isSwitchingLanguage }}`, and informative `accessibilityLabel` with native label, localized name, and reading direction.

### C. Concurrency & Persistence Contract Preserved
- `isSwitchingLanguageRef.current` concurrency guard prevents overlapping switches.
- `disabled={isSwitchingLanguage}` on all cards during in-flight switches.
- `haptic('selection')` on user interaction.
- `Promise.resolve(setLanguage(nextLang)).then(...)` preserves atomic serialized write-and-verify queue.
- `prepareNativeLayoutDirection(nextLang)` sets native layout direction prior to `Updates.reloadAsync()`.
- Unmount and timer safety: `reloadTimerRef` cleared and managed cleanly without cancellation leaks.
- Error state: Catches persistence failures, reverts refs, and displays `setLanguageError`.

## 5. Remaining Physical-Device Checks

Per rule 21 ("No physical-device claims without a device"), static and bundle exports are verified. When testing on physical devices:
1. **RTL Direction Switch on Android**:
   - Switch language to Urdu or Arabic: verify native reload triggers via `Updates.reloadAsync()`, the app boots with RTL direction enabled, and cards display with title on right and radio indicator on left.
   - Switch back to English, Hindi, Malayalam, or Sinhala: verify native reload triggers with LTR layout direction restored.
2. **Complex Script Native Font Shaping**:
   - Verify Sinhala (`සිංහල`), Malayalam (`മലയാളം`), and Hindi (`हिन्दी`) system font fallbacks on older Android (Android 10/11) and iOS versions to confirm no missing glyph rectangles ("tofu").
3. **Screen Rotation & Foldables**:
   - On a physical foldable or tablet, rotate between portrait and landscape: verify seamless re-render from 2 columns to 3 columns without jump or card overflow.
4. **Accessibility TalkBack / VoiceOver**:
   - Inspect focus order across the language cards, ensuring screen readers announce the native name, localized subtitle, direction, and selected status correctly.
