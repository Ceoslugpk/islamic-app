# Rebuilt Continue Reading Restoration around Exact Mushaf-Page-First Architecture

## 1. Executive Summary & Root Cause Analysis

### Background
When a user tapped "Continue Reading", the app previously frequently opened the wrong position (e.g. Page 1, Ayah 1, or the wrong Surah) and failed to visibly highlight the restored Ayah. Investigation revealed several intersecting root causes:

### Root Causes
1. **Unconditional Full Surah Fetch & Eager Mount**:
   `loadSurah()` was invoked on mount inside `QuranReaderScreen.tsx` regardless of `readingMode`. For large Surahs like Al-Baqarah (286 ayahs), this triggered massive JSON downloads and ayah array processing across the network/cache before Mushaf mode was ready.
2. **Eager Position Overwrite on Mount**:
   In `loadPageData()`, when the target ayah was not immediately mapped in memory or when the page first arrived, the code had a fallback `data.ayahs[0]` that called `saveReadingPosition(...)`. This immediately overwrote the user's saved reading position with Ayah 1 of the page before layout or user interaction could take place.
3. **Premature Highlight Triggering & Expiration**:
   `flashMushafAyah()` was scheduled immediately upon data receipt using a simple timer. Because DOM/Native layout and element measurement take time, the 2000ms timer expired before the rendered Ayah row was mounted and visible on screen, resulting in zero visible highlight.
4. **Unstable & Non-Unique Highlight Key**:
   The highlight state tracked `highlightedAyah` as a global ayah number (`a.number`). On pages containing multiple Surahs, or across Surah boundaries, global ayah comparisons led to ambiguities. The key needed to be compound: `${surahNumber}:${ayahNumber}`.
5. **Loss of `page` Parameter Across Navigation Layers**:
   In `App.tsx`, `handleOpenQuran` accepted `(surah, initialAyah, initialPage)`. However, if `initialAyah` was passed without `initialPage`, the fallback marker lookup logic was skipped, causing `initialPage` to become undefined and defaulting Mushaf mode to deriving the page from the first ayah of the Surah.
6. **Asynchronous Cache Miss on Web Cold Boot**:
   `getReadingMarkerSync()` and `getReadingPositionSync()` in `src/lib/continuing.ts` relied entirely on in-memory cache refs which were `null` immediately after page reload on web before `initializeReadingPositionCache()` finished.

## 2. Exact Files Modified

1. **`src/lib/continuing.ts`**:
   - Added synchronous web `localStorage` lookup fallback to `getReadingMarkerSync()` and `getReadingPositionSync()` when in-memory cache refs have not yet resolved on clean boot.
2. **`App.tsx`**:
   - Updated `onOpenReader` and `onOpenQuran` callbacks in `HomeScreen`, `QuranHomeScreen`, and `onNavigateSurah` to consistently pass and resolve `initialPage` via `getReadingMarkerSync`, `getReadingPositionSync`, and `getMushafPageForAyah`.
3. **`src/screens/HomeScreen.tsx`**:
   - Updated `handleOpenReader` to accept and pass `(surah, ayah, page)` to `onOpenReader` and `onOpenQuran`.
4. **`src/screens/QuranHomeScreen.tsx`**:
   - Updated `handleResumeReading`, recent surah chips, and surah list clicks to pass `initialPage` alongside `surah` and `ayah`.
5. **`src/screens/QuranReaderScreen.tsx`**:
   - Initialized `readingMode` synchronously to `'mushaf'` whenever `initialPage` is present or persisted in `quran-reading-mode`.
   - Used `initialPage` as the authoritative initial Mushaf page without derivation from guessed surahs.
   - Gated `loadSurah()` strictly to `readingMode === 'cards'`, preventing any full-surah download or pre-render in Mushaf mode.
   - Attached `ref={mushafListRef}` to single-page FlatList.
   - In `loadPageData()`, matched target ayah with both `a.surah.number === target.surah && a.numberInSurah === target.ayah`.
   - Removed fallback `saveReadingPosition()` call during restoration so saved position is never overwritten before user interacts.
   - Tied highlight to stable key `${surah}:${ayah}` and triggered the 2000ms timer only upon `onLayout` (`handleMushafAyahLayout`) of the restored ayah row.
   - Ensured action popup remains closed during restoration and highlight.
   - Added cleanup to clear highlight on page turn, unmount, or manual ayah selection.
6. **`tests/test_stage2_reader_position.mjs`**:
   - Updated highlight assertions to validate stable `${surah}:${ayah}` key structure and isolated popup behavior.
7. **`tests/test_continue_reading_page_first.mjs`**:
   - Added dedicated 5-point regression test suite verifying end-to-end page passing, authoritative initialPage, Surah+ayah matching, layout-driven 2000ms highlight, and lazy surah loading.
8. **`package.json`**:
   - Added `test_continue_reading_page_first.mjs` to `npm test`.
9. **`scripts/web_qa_test.mjs`**:
   - Created automated Playwright headless Chromium QA test testing clean app boot, hard refresh, seed storage, DOM verification, 2000ms highlight window and expiration, and multi-surah page handling.
